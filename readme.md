# Учебный проект Task Manager

Простой REST API проект для управления задачами (работами, заданиями), написанный на FastAPI. Проект создан для изучения основ разработки на FastAPI Python, использования Git, CI/CD и контейнеризации.

---

## 📝 О проекте

Приложение реализует базовые CRUD-операции (создание, чтение, обновление, удаление) для задач.  
В текущей версии (результат выполнения **практических работ №4 и №5**) реализовано:

- **FastAPI** и автоматическая документация Swagger UI;
- работа с JSON и Pydantic-схемами;
- **Тестирование** (pytest) с покрытием кода более 70%;
- **CI (Continuous Integration / Непрерывная интеграция)** - автоматическая сборка и проверка кода;
- рефакторинг структуры кода (выделение моделей, роутеров и БД);
- добавлен новый метод API (по варианту 1: PATCH);
- проверка безопасности (bandit), интегрированная в CI;
- **Контейнеризация (Docker)**: многоэтапная сборка (`multistage`), оптимизированный образ;
- **Docker Compose**: связка приложения с базой данных **PostgreSQL**;
- **SQLAlchemy**: переход от хранения данных в памяти к реальной базе данных;
- **Volumes**: сохранение данных PostgreSQL при перезапуске контейнеров.

## 📚 API Endpoints

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/tasks` | Получить список всех задач |
| POST | `/tasks` | Создать новую задачу |
| GET | `/tasks/{task_id}` | Получить задачу по ID |
| PUT | `/tasks/{task_id}` | Обновить задачу по ID |
| DELETE | `/tasks/{task_id}` | Удалить задачу по ID |
| PATCH | `/tasks/{task_id}` | Частичное обновление по ID |
| GET | `/health` | Проверка работоспособности приложения |

## 📋 Модель задачи (Task)

Модель описывает структуру данных задачи и валидируется с помощью библиотеки **Pydantic**.

**Основные поля:**
- `id` *(str)* — уникальный идентификатор задачи (генерируется автоматически как UUID).
- `title` *(str)* — заголовок задачи. Обязательное поле, **от 1 до 100 символов**.
- `description` *(str | None)* — описание задачи. **Опционально**, до 500 символов.
- `is_completed` *(bool)* — статус выполнения. По умолчанию `False`.
- `priority` *(Enum)* — приоритет задачи. Допустимые значения: `low`, `medium`, `high`. По умолчанию `medium`.
- `created_at` *(datetime)* — дата и время создания (генерируется автоматически).
- `updated_at` *(datetime)* — дата и время последнего обновления.

**Особенности частичного обновления (PATCH).** Для частичного обновления используется модель `TaskPatch`, где **все поля являются опциональными**. Если в запросе передается только одно поле (например, `{"is_completed": true}`), остальные данные задачи остаются без изменений.

## 🚀 Как запустить проект (Docker)

Для запуска требуется установленный **Docker** и **Docker Compose**.

1. **Соберите и запустите контейнеры (приложение + база данных):**
   ```bash
   docker compose up -d --build
   ```

2. **Проверьте статус контейнеров:**
   ```bash
   docker compose ps
   ```
   *(Оба контейнера — `app` и `db` — должны быть в статусе `Up`)*.

3. **Наполните базу данных начальными задачами (опционально):**
   ```bash
   docker compose exec app python seed.py
   ```

4. **Проверьте работу API:**
   Откройте в браузере **http://127.0.0.1:8000/docs**

5. **Остановка проекта:**
   ```bash
   docker compose down
   ```
   *(Данные в базе сохранятся благодаря volumes и будут доступны при следующем запуске)*.

## 🧪 Запуск тестов

Тесты используют SQLite в оперативной памяти (подмена через Dependency Override), поэтому для их запуска не требуется база данных PostgreSQL. Выполните:

```bash
docker compose exec app pytest
```
